# 新增记录射门实验的复现代码候选

本目录提供衔接的本地代码，支持新增的球员状态记录射门实验。它不是完整CCPV论文的公开代码，也未获得所有作者或第三方的再分发许可。所有原代码、历史结果和失败记录仍保留。当前资料已曝光，重新执行属于结果重建，不能作为新的独立验证或重新调参。旧31文件压缩包保持原样，后续模块另打新版本。

- `development_grid/`：七场原始时间元数据生成13,372行候选格，按原全局编号导出六场11,542个候选。旧标签和模型结果不参与候选生成。
- `development_clock_sources/`：原始XML及ELASTIC作者parquet重建直接时钟、严格作者身份映射和固定40毫秒诊断案例。固定案例的选择器可由独立补充模块 `development_clock_selector/` 从指定原始事件XML恢复；不搜索最优时间偏移。
- [原始事件到开发标签](development_event_labels/README.md)：重建事件版本/有效性与双时钟方案，再结合原始PLAYER当前/过去坐标和未来时间戳，重建原始两点特征、全部标签、未知原因与事件关联，不读取旧标签表或旧特征缓存作为生成输入。
- `development_lofo/`：上述原始两点特征 → 六场留一比赛×五种子×两臂，共60个固定训练头和对应预测/评分。与部署头、六点共支持对照分开。
- [六点共支持开发特征](development_features/README.md)：可接受新重建且与原件同值的标签表，结合保存历史或原始PLAYER XML，生成native/grid × 200ms/OLS1s特征。该模块原有 `UPSTREAM_LABELS.md` 是上游来源清单；新上游入口见本页前三项。
- `development_history_coverage/`：由已重建的历史掩码、两套特征及完整标签表生成11,542行历史覆盖表；不必另取无法生成的旧coverage缓存。
- `development_motion_lofo/`：共支持特征 → 六场留一比赛×五种子×三臂的90个训练头，再分别读取native/grid两条件。两条件不另训两套模型；history_coverage输入的来源须同时保留。
- [固定部署训练](external_head_training/README.md)：同一共支持特征缓存生成三个模型×五种子的部署头，原定每头200次更新。模型、种子、资格与超参数不重新选择。
- [固定九场验证重建](external_shot/README_zh.md)：原始GSR或已保存特征经固定模型产生预测；预测冻结之后单独读取BAS事件评分，并与原结果逐项比较。

这些入口采用显式输入路径和全新输出目录。数据、逐窗缓存、标签、历史轨迹、训练索引及模型权重不在代码压缩包内；运行时产生的衍生物须保存在用户授权的私有目录。输入文件及数值契约均以固定摘要说明，不能用其他比赛或筛选后的窗口悄然替换。

采用原Python 3.11.5、NumPy 1.26.4数值环境；原始DFL XML还需要lxml。各子目录requirements.txt给出实际依赖。其他平台或数值后端须重新验证，不声称已跨平台认证。

交付验证记录放在本目录外，分别报告缓存重建、迁移目录重建和原始文件重建的实际范围。本目录的历史说明可能先于随后完成的原始文件验证；以各次执行日期、完成状态和输入范围为准，不能把未执行入口写成已执行。

完整论文仍需核查部分旧神经模型训练/推理入口及其派生输入路线，以及所有保留结果的合法输入与持久公开版本。不同训练矩阵必须分别核验，不能用15部署头代替60或90留一比赛对照。局部数值重建成功不证明真实跑位因果收益、进球概率改善、原420场数据规模或整套CCPV的有效性。
